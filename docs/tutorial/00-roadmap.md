# Дорожная карта: глубокое освоение Nix

Этот tutorial рассчитан на linux-пользователя без NixOS, который хочет:

1. Понять Nix не поверхностно ("скопировал flake.nix из интернета"), а на уровне механики — язык, derivations, store, purity.
2. Научиться собирать C++ проекты, у которых есть **дерево зависимостей между отдельными git-репозиториями** (GitHub/GitLab), а не один монолитный репозиторий.
3. Уметь **переопределять источник сборки по ветке** во всём дереве репозиториев одновременно: если существует custom-ветка `special-123123_add_feature` — собирать её везде, где она есть; если её нет в конкретном репозитории — падать обратно на базовую ветку `special`.

## Как читать

Главы пронумерованы и рассчитаны на последовательное чтение — каждая следующая использует термины из предыдущей без повторного объяснения. Главы 05–07 — практические: рядом лежит рабочий код в `../examples/`, который нужно реально собирать руками (`nix build`), а не просто читать.

## Оценка времени

- Главы 01–04 (теория): 1–2 вечера, если делать упражнения в `nix repl` по ходу чтения.
- Главы 05–07 (практика с C++): 2–3 вечера — тут стоит реально прогнать примеры, а не просто прочитать.
- Главы 08–11: по мере необходимости, не обязательно проходить подряд.
- Глава 12: отдельно, после главы 04 (нужны только flakes, C++-главы 05–10 для неё не требуются) — 1 вечер, практика уже лежит в корне репозитория.

## Чек-лист самопроверки

- [ ] Понимаю разницу между Nix store path, derivation и built output.
- [ ] Могу объяснить, почему `import ./foo.nix` — это просто вызов функции.
- [ ] Знаю, зачем нужны `nativeBuildInputs` отдельно от `buildInputs`.
- [ ] Могу с нуля написать `flake.nix` с `packages.default` для CMake-проекта.
- [ ] Умею подключить второй flake как `input` и использовать его `packages.${system}.default` как зависимость.
- [ ] Умею объяснить, почему `nix build` не может "просто проверить, есть ли ветка на GitLab" без `--impure` или внешнего скрипта.
- [ ] Умею писать скрипт, который определяет наличие custom-ветки во всех репозиториях дерева и подставляет её как override.
- [ ] Понимаю разницу между "переопределить исходники по ветке" (глава 07) и "переопределить атрибуты derivation" (глава 08).
- [ ] Умею получить граф derivations в JSON (`nix derivation show -r`) и отфильтровать его до своих пакетов.
- [ ] Умею сгенерировать GitLab DAG-pipeline из этого графа так, чтобы независимые узлы дерева собирались параллельно на разных раннерах.
- [ ] Понимаю разницу между `home.packages` и `programs.<name>.enable` в home-manager.
- [ ] Умею объяснить, почему `home.stateVersion` фиксируется один раз и не обновляется вслед за home-manager.
- [ ] Умею применить конфиг для конкретной машины (`home-manager switch --flake .#<host>`) и откатиться на предыдущую generation.

## Внешние источники (для углубления, не обязательны для прохождения tutorial)

- <https://nix.dev> — официальный практический учебник.
- <https://nixos.org/manual/nix/stable/> — референс Nix.
- <https://nixos.org/manual/nixpkgs/stable/> — референс nixpkgs (stdenv, lib, builders).
- <https://zero-to-nix.com> — короткое современное введение, ориентированное на flakes.
- Nix Pills — глубокое погружение в устройство derivations "снизу вверх" (полезно после главы 03).

## Структура репозитория этого tutorial

```
tutorial/           — главы 00-11, читать по порядку
examples/
  libC/              — листовая C++ библиотека (флейк)
  libB/              — библиотека, зависящая от libC
  app/               — исполняемый проект, зависящий от libB (и транзитивно от libC)
  scripts/select-branch.sh         — реализация branch-fallback логики (глава 07)
  scripts/generate-dag-pipeline.sh — генерация GitLab DAG-pipeline из графа Nix (глава 10)
  ci/                — шаблоны пайплайнов GitLab CI / GitHub Actions (глава 09)
  README.md          — как связать три примера локально и переключить на реальные GitHub/GitLab URL
```
